# 按原文章节整理可回查的文献笔记

先写章节树与范围清单，保留原有章节名。把摘要中的发现追回结果表，再找方法中的分母、比较组、样本选择与测量窗口，建立同一研究对象的证据链。遇到综述、理论或定性研究，按原文结构调整类别，说明不适用原因。

- 每条笔记只记一个事实或作者解释，保留数值、单位、组别、样本量、误差和条件。将作者结论、论文引述的他人观点、读者推断分开。摘要和表格不一致时并列原值和来源。
- 每项引证包含 file、从 1 起算的 lines、原文 quote 和原始 locator。PDF 先按真实页面导出 UTF-8 转录，核对版面，并把原文件与页表号写入 locator。脚本会拒绝对不上指定行的引文。
- 为每章或指定范围生成 notes，按研究问题、数据、方法、结果、结论、限制查漏。没有报告的信息可填 state=unreported 和 searched 来说明查过哪里；不能仅凭检索不到便断言作者未研究。跨章节同一结果只建一张主卡，其他地方引用其 ID。
- 由卡片提炼开头的摘要，每句引用一个或多个卡片 ID。优先讲研究问题、最重要的带条件发现、解释边界。交付带章节笔记、卡片、来源和剩余缺口的可编辑成果。

逐句核对原文到卡片、卡片到摘要。先确认每个结果属于哪个组、哪项指标、哪个时间点，再对照数值、单位及样本量。双组并列时，按组名出现的次序逐个绑定对应值，核对两项各自的单位、误差和比较符。组名和数值一起换序可保留；只交换数值时检查对应的组。两组共享单位或明确报告样本量时可保留“分别”表述。组名缺失、对应项数不等、跨时间点或多个指标混写时，先回到原文拆成带条件的独立结果。合计与亚组、入组与完成随访人数也要分开核实。跨语言或缩写可在顶层 group_aliases 提供原文名与译名到同一组名的映射，例如 `{"Site Alpha":"alpha","甲站":"alpha"}`。同名对象的定义与统计口径仍须回读原文。

脚本在已支持的量纲内按精确比例核对单位、范围和 ± 误差，保留比较符号；样本数单独核对，可使用 n=8、sample count、8 participants 或“样本量为 8”等明确表述。单位符号区分大小写。百分比与百分点、温标变换、派生统计量、未收录单位和未识别的自由表述须附原量、公式与来源人工复算。摘要可保留正确换算后的可读单位。

通过核查的卡片写入 cards.json，章节与摘要写入 notes.md；引文保留在末尾便于复核。待确认的提法、所引卡片或证据 ID 及原因位于 pending.json。某张卡片待核时，引用它的摘要也会暂缓进入成稿。优先用原文修订这些片段并重新运行，以免遗漏用户要求的字段。若证据不足，明确标示缺口。

### 从实际文件建立原文索引

在工作目录执行 `python /skills/weekly-skill/scripts/prepare.py 案例ID 索引目录 原始文件 [其他文件 ...]`。支持 UTF-8 文本、Markdown、逐行配置与 DOCX 正文段落和表格；原生文字 PDF 可选用 pypdf（Python 包），没有时用评测环境已有 PDF 阅读器转录。生成的 source.txt 和 inventory.json 保留原文块、来源位置、文件指纹和引文行号。把本题中间 JSON 与 source.txt 放在同一目录，按需选用 evidence 或 source_blocks。PDF 多栏、扫描页、Word 合并单元格、页眉脚注和公式须对照原件；索引只帮助定位。

## 在评测环境中使用

读取 /input/case.json、task.md、output_contract 和实际附件。记录 case_id、任务语言、受众、指定格式与证据范围。把下面示例中的字段换成当前案例的实际材料。先在 /app/work 处理，最终把成稿、必要的可编辑附件和 /app/output/result.json 放入 /app/output。保留原 output_contract 的字段名、类型与 case_id，将主结果、来源、修改记录、未解问题和状态填入相应字段。review.json 是本地机械检查的报告；语义判断、任务覆盖及正式结果须由执行 Agent 完成。材料缺失时交付可核查部分，标明缺失处。若案例要求 Office 或图形产物，生成指定格式，并打开实际渲染的 PDF/PNG 预览检查。

## 最小调用示例

最终成稿可先写成 /app/work/draft.json，将所需独立产物写到 /app/output，再运行 `python scripts/finish.py /input/case.json /app/work/draft.json /app/output`。用 `--artifact 文件名` 逐个检查附带的真实成品。它检验 case_id 和顶层必需字段并原子写入 result.json；若字段来自文字合同，用 `--require 字段名` 指明。字段类型、嵌套结构与科学内容仍要按案例核对。

从本 Skill 根目录运行下列命令，或将 scripts/run.py 替换为安装目录 /skills/weekly-skill 下对应的绝对路径。辅助脚本使用 Python 3.9 或更高版本及标准库。输入、引文与样例数据均为自建示例。

```sh
python scripts/run.py examples/input.json sample-output
```

示例把室内结果 N1 链回 E1，室外结果保留为材料缺口。有复核项时阅读 review.json，修正实际发现的问题后选新的输出目录重跑；脚本遇到输入格式错误会退出并说明位置。
